# 业务需求与当前验收边界

目标是以一个虚构调查应用学习企业全栈软件工程。固定一案、六条证据、三个相关人员，不扩大为协作或角色审批产品。

| 模块 | 行为与规则 |
|---|---|
| 案件 | 浏览、开始个人调查、恢复原调查 |
| 证据 | 查看标题/摘要，依发现前置解锁；未调查正文不返回 |
| 关联 | 已发现的两端建立无向关系；不自环、不反向重复；调查中可修订类型与解释，保留 ID/端点 |
| 进度 | 保存笔记/恢复；Active→Reviewing→Submitted，Reviewing可返回Active；版本冲突与重复意图受保护 |
| 结论 | 合法人员、20–4000字符说明、三条不同已发现支持证据；确定性教学评分，终态只读 |

解释 Trim 后按 Unicode scalar 计20–500，旧关联允许解释/时间均为空。复核需要至少三条发现、两条关联。评分按人员与支持证据集合计算，关联解释不参与判断。

调查只对所有者可见；所有者来自身份票据。写入需要 CSRF 和 UUID 幂等键，已有调查另需强整数 If-Match。成功聚合、审计、回执同一事务；版本/领域拒绝不留下部分状态。历史回执确认原提交，不能当作最新资源。

前端保留草稿基线与编辑代次，后台读取不能静默换成较新写版本；显示冲突并显式确认。保存期间后来输入保留，未知结果用原请求确认；生成类型由 OpenAPI 核对。

当前个人列表只取最近50份，草稿只保留页面生命周期。账户恢复/MFA/会话治理、回执清理、防篡改审计不是已实现能力。

应用代码、数据库模型/迁移、独立测试、轻量CI与全栈教材源归本仓库。2026-11-11范围决议明确排除环境交付与运维，见 ADR0009。五模块与应用正确性是验收对象，不以云发布作为完成条件。
