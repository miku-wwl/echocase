# ADR 0001–0006：关键取舍

历史记录：以下描述截至 `bf9de37b9bd4d5cc2c227af2c857360e048b15d1` 的决策。ADR 0002 已由 [ADR 0010](0010-template-first-foundation.md) 替代；保留原文以说明此前确实未以官方生成模板为基础。

| ADR | 决策 | 选择原因 | 代价与重新评估条件 |
|---|---|---|---|
| 0001 | 四层模块化单体 | 同一调查的本地事务足以覆盖需求 | 功能增加时拆应用用例文件，保持边界；不预设服务化 |
| 0002 | 借鉴 Jason Taylor，不整体生成模板 | 已阅读机制；避免引入 Todo/Aspire/通用总线等无关部分 | 这是原创实现，不声称已跑上游模板全部测试；出处独立记录 |
| 0003 | 显式整数 Version | 映射 HTTP 强 ETag，便于解释和跨层测试 | 所有子记录变更必须推进根版本；不等于完整 HTTP 条件规范 |
| 0004 | PostgreSQL advisory lock + 原子回执 | 支持多进程相同键串行化并返回原响应 | 锁协议必须统一，回执保留与容量待治理 |
| 0005 | Identity Cookie + CSRF、同源前端 | 不自创密码机制、不把票据放 localStorage | 多域与外部 OIDC 需重评；没有完整生产账户治理 |
| 0006（历史） | 旧阶段本地优先/云设计 | 当时的范围选择 | 已由所有者批准的ADR0009替代，不是当前目标 |

没有继承上游业务源代码；官方 shadcn 组件和所需样式保留 MIT 来源。详见仓库 THIRD-PARTY-NOTICES.md。
