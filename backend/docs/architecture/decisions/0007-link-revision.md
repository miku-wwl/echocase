# ADR 0007：修订现有关联，保留身份与旧记录

状态：选定并实施；执行结果见当前应用验收。

需求：调查员在调查中发现两条证据的关系判断有误，应能修正关联类型并解释判断，而不是删除重建。范围仍为证据关联模块，不增加审批、协作、角色或案件。

合同：`PUT /api/investigations/{id}/links/{linkId}`，正文 `kind` 与 `rationale`，沿用所有权、CSRF、If-Match、幂等回执。根聚合版本推进一次，关联 ID 与端点不变。Reviewing/Submitted 拒绝修改。解释按 Unicode scalar 数计 20–500，先 Trim，避免 .NET UTF-16 与 PostgreSQL char_length 对 emoji 计数不一致。

迁移：新增可空 Rationale 和 RevisedAt，成对为空或成对存在；旧数据不伪造解释或时间。新 API 返回可空字段，旧创建合同保持不变。旧回执反序列化必须容忍缺这两个新增字段。新记录也可在创建后首次修订补解释。

替代：删除重建会改变链接身份并让“纠正判断”表现成两个不相关动作；强制为旧记录补默认解释会伪造分析；新增修订历史/审批模块不符合当前需求。当前只保留最新解释和已有操作审计，不声称完整历史或不可篡改审计。

模式兼容：Down会删除新增字段，不能等同数据无损可逆。旧二进制兼容验证属于历史Phase2A；当前应用范围保留旧数据迁移与旧回执测试，不维护环境切换自动化。

实测修正：.NET tick 为 100ns，PostgreSQL 时间戳保存到微秒。首轮测试即时响应为 `639299746962572167` tick，重新读取为 `639299746962572160`。应用边界把业务时钟截到微秒后再传入领域，回执与数据库快照精确一致。该精度属于 API 合同；领域不引用 PostgreSQL。旧回执仍按原样返回，不改写历史回执来假造一致性。历史前后记录见基线63c5872的evidence/phase2a；当前测试继续断言即时响应/数据库重读一致。
