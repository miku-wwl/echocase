# ADR 0008：草稿基线与服务端缓存分离

代码审查确认的风险：dirty 草稿如果随着 refetch 使用新 Version 保存，就把未经用户确认的内容覆盖到新事实；保存回调若无条件清 dirty，会丢掉请求发出后继续输入的文字；原幂等回执并不代表最新快照。

选择：专用调查 hook 管理 Query/命令；专用草稿 hook 保存编辑开始时的 notes/version 和编辑代次。提交使用草稿基线，不自动换成后台新版本。成功只确认发出的内容，不清除后来编辑。已知冲突展示服务端与本地内容，需显式确认后生成新意图。未知结果仅重试原命令（键、版本、正文不变）。服务端缓存按版本单调接受快照；乐观笔记使用单独呈现层，不伪造“已确认”服务器版本。

查询消费 AbortSignal，取消真正到达 fetch；取消不转换为未知写结果。当前不增加通用全局 store、自动文本合并或协作协议。草稿只保留当前调查页面生命周期，浏览器关闭恢复仍非本阶段目标。

由真实延迟请求、后台刷新、多窗口和提交后丢弃响应的测试验证；注入点与真实数据库提交必须分别记录。
