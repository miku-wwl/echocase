# 序言：沿着一次保存，读懂整个系统

调查员按下“保存”，又在输入框补充了一条线索。服务器已经提交前一句话，成功响应却还在路上。响应回来时，输入框应该显示什么？页面能否写“已保存”？如果另一个窗口也修改了档案，这次成功还能覆盖当前界面吗？这些问题贯穿业务规则、数据库事务、HTTP 协议和浏览器状态。本书要解释的，正是一个普通按钮背后相互依赖的承诺。

EchoCase 是一个体量受控的调查档案应用。固定案件、证据解锁、关系修订、复核与结论封存，提供了足够具体的业务约束，又不要求读者预先掌握复杂行业知识。实现使用 ASP.NET Core 10、EF Core、PostgreSQL、React 19、TypeScript、TanStack Query 和 React Flow。新版还深入解释官方 CleanArchitecture 模板引入的 MediatR、FluentValidation、端点发现、身份抽象及 NSwag 客户端。

## 这一次修订改变了什么

早期 EchoCase 是自行实现的分层应用。它虽然有领域根、存储端口和事务协议，却未履行原 README 要求的“以官方模板为基础”。后来才实际生成 Jason Taylor 的 `Clean.Architecture.Solution.Template@10.8.0`，独立验证生成基线，再迁入业务实现。新版不会把这段纠偏改写成“从第一天就使用模板”。第二章用真实来源区分保留、适配与移除的机制。

本版工程源码固定为 `9f68721e18f15ae603e6502fa46b8fa78f9df55c`，不是随 main 浮动的最新代码。官方上游对应 `e5c08ecead8a52f6cf519477bf6c57668248c035`，生成基线保存在 `f1df1a3c3b95bae184600a0ccef629eccaa18080`。出版日期为 2026 年 11 月 13 日。历史 107 页版本独立保留，新版使用独立章节、图源、清单和 PDF。

## 如何阅读这本书

读者应具备基本 C#、SQL、HTTP 与 React 经验。前六章从需求、聚合和依赖方向进入两层请求管道及生成式客户端；第七至十一章解释跟踪、演进、MVCC、竞争和回执；第十二章接回身份与资源边界；第十三至十六章解释浏览器如何保护尚未提交的工作；最后以查询计划、验证推理、完整需求演进和设计题收束。

第一次阅读可以沿“修订一条关系”的主线前进，暂时跳过源码中的辅助字段。第二次阅读应反过来推演失败：若旧版本晚到、回执被前所有者重放、性能日志在提交后又查询数据库，哪一层仍有权改变结果？[第十九章](19-evolution.md)把各层真实源码接起来，检验前面建立的模型能否解释完整变化；需要补充跟踪、快照或草稿前提时，可回到[第七章](07-persistence.md)、[第九章](09-mvcc.md)与[第十五章](15-drafts.md)。

每个源码框都从固定 Git 对象提取，显示路径、行号与上下文链接。历史模板比较会另标来源。软折行没有创造新的源码行号；省略的上下文可以沿链接查看。机制图的时间轴表达先后与因果，不按真实耗时比例绘制；教学示意与实际运行观察会明确区分。

## 真实材料的适用边界

九组真实界面与数据库观察采自 2026 年 11 月 11 日的 `63c5872` 历史运行。它们没有被改称为迁移后的新截图。领域根、应用协调服务、EF 映射和 PostgreSQL Store 在两个版本间保持相同内容，所以相关跟踪、事务和查询观察仍可用于解释这些机制；请求分派与客户端已经改变，新版使用当前源码重新说明。

图中的界面揭示草稿、冲突和确认状态，不充当新版验收的替身。数据库执行时间来自单机合成数据的暖缓存观察，不是当前环境复测、生产指标或服务承诺。书中不会用未执行的反事实推演冒充复现结果。详细来源、复现入口和出版审校记录放在教材源的参考目录，正文保留有助理解的结果和解释。

EchoCase 读写共用一个数据库，没有 Event Sourcing、独立投影或消息总线。回执没有自动清理，草稿没有跨页面恢复，图位置只在当前视图中保留，身份功能也不是完整企业账户治理。理解这些边界，才能判断什么时候应保留当前设计，什么时候必须改变。

## 一条贯穿全书的判断标准

理解框架意味着能够预测边界情况。读完请求章节，应能指出 ASP.NET 中间件和 MediatR 行为分别包住什么；读完 EF 章节，应能解释跟踪器为何已经显示 Unchanged，显式事务却仍可能未提交；读完 React 章节，应能解释一次成功为何不能抹掉下一代输入。

本书反复追问四件事：事实来自哪个时刻，正在确认哪一次意图，决定由谁拥有，失败后还能相信什么。答案落在真实对象、语句、事务、响应和屏幕上。沿着这些联系，一次保存才从“接口返回成功”变成可以推理的系统行为。
