# EchoCase 产品与验收边界

目标用户是学习与演示中的调查员；所有案件资料虚构。MVP 固定一案、六条证据、三个相关人员。业务行为：登录后浏览案件并开始个人调查，依前置规则调查证据，建立无向印证/矛盾关系，保存笔记，复核并提交有支持证据的结论。

## 可验收约束

- 调查仅对所有者可见；ID 不是授权凭据。
- 未调查正文不返回，前置发现决定解锁。
- 关联两端必须已发现，不允许自环、反向重复或同一对的多类型重复。
- Active 状态可修订已有关联的类型与解释；解释 Trim 后按 Unicode scalar 计 20–500，保留关联 ID 与端点，推进调查版本一次。旧关联可没有解释，不补造历史。首次创建的原合同保持不变。
- Active 可编辑，至少三条发现与两条关联方可 Reviewing；Reviewing 可 Resume；Submitted 终态只读。
- 提交需要合法人员、20–4000 字符说明、至少三条不同已调查支持证据。
- 所有调查写操作需要 UUID 幂等键；已有资源写操作另需强版本 If-Match。
- 成功写入同时提交聚合、审计与回执；失败不留下部分状态。
- 个人列表目前只展示最近 50 份调查，没有分页或协作共享。

不在初始范围：AI、真实案件、复杂故事、多人协作、多租户、微服务、Kubernetes、外部消息交付。账户恢复、MFA、邮箱确认、长期审计治理与生产会话撤销尚未实现；真实用户上线前必须补齐适用能力。
