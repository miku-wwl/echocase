## 五模块、T1–T5、Stage 与 DoD

五模块仍为案件、证据、关联、调查进度、结论。仅关联增加修订动作；原真实浏览器全过程与新 OCI 结案路径分别验证它们，没有增加角色、协作或案件数量。

| 目标 | 当前证据与边界 |
|---|---|
| T1 Clean/DDD | 依赖测试、根修订规则、ADR 0007/0008、固定模板源码比较；没有声称实现所有 DDD 模式 |
| T2 EF/PostgreSQL | 实际跟踪状态、SQL、根条件更新、旧数据迁移、事务竞争、真实列表执行计划；没有生产负载结论 |
| T3 React | 拆分职责、dirty 基线/编辑代次/缓存单调性/错误恢复/React Flow 修订；未实现协同合并或跨关闭恢复 |
| T4 安全/一致性 | 真实 Cookie/CSRF/资源过滤/严格合同/条件写与幂等；仅已测试的保护，不等于完整生产安全 |
| T5 测试/交付 | 风险驱动的原回归与新因果断言、故障诊断、OCI 生命周期与 CI；Azure 实施未执行 |

Stage 1–3 的领域、真实持久化/API、前后端闭环已实现并重新验证。Stage 4 的质量/性能/可复现交付与 Stage 5 的变更评估通过 A–E 验收。**Stage 0 按原字面为 PARTIAL**：没有初始化 Jason Taylor 整体模板、没有运行其原测试，选择源机制审查和原创有限实现；Phase 2 指令明确允许不重建仓库，这一偏离继续公开，不用本项目测试替代上游测试。

原 DoD 的干净环境、五模块、领域约束、数据并发、授权、完整浏览器链、可复现交付、实验/ADR，分别由 A–E 与流水线结果核对。工程结论、教材编辑目标和云/生产限制在验收报告中分开；97 页冻结 PDF 不是 300–400 页教材目标完成证明。
