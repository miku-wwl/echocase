# Phase 2A 发布说明与变更影响

## 用户可见变化

调查中可以在原关联上修订“相互印证/存在矛盾”和解释，无需删除重建。解释为 Trim 后 20–500 个 Unicode scalar，保留关联 ID、调查、端点。旧关联显示原关系，解释为空；不会生成虚构历史。复核与已封存调查继续只读。

修订不改变固定的教学评分：人员和支持证据集合决定分数，关联类型/解释尚不参与评分。没有自动判断解释真伪的能力。

笔记保留编辑开始的内容和版本。保存过程中继续输入不会被晚到响应删除；后台刷新发现版本变化后展示编辑前/当前/草稿，明确确认才覆盖当前内容。网络中断后原键重试，先确认原操作再继续写入。较旧回执不能把页面版本倒退。

## 逐层影响

| 层/合同 | 变化 | 兼容与验证 |
|---|---|---|
| 需求与决策 | PRD、ADR 0007/0008 | 同一关联模块，五模块与单案件保持范围 |
| Domain | Investigation.ReviseLink；子关联内部 Revise | Active、身份/端点、长度、无变化约束；根版本只加一次 |
| Application | ReviseLinkRequest/用例；LinkView 两个可空默认字段；业务时间精度 | 旧回执 JSON 可读；旧创建请求合同保留；即时回执与 DB 读取微秒一致 |
| API | PUT links/{linkId}；ProblemDetails 追踪编号统一 | 所有者/CSRF/键/If-Match 保护共享；类型只接受命名值；OpenAPI 类型重新生成并由 CI 比较 |
| EF/PostgreSQL | `20261111060117_LinkRevisionExplanation` | nullable Rationale/RevisedAt 与成对 CHECK；旧数据原样保留；旧镜像可在扩展表上读写 |
| React | Workspace 与协议/草稿/笔记/关联编辑职责拆分 | 原 App 1018 行变为 475 行，并非以行数判质量；实际失败时序由回归验证；图谱布局仍为本地呈现 |
| 运维 | old→new→停库→old→new 的 OCI 生命周期 | 共享命名 DataProtection 卷，Cookie 重建可用；每次演练随机资源前缀，退出清理本次资源 |

## 发布和回退顺序

1. 从已审查源构建新版和固定基线镜像；先跑领域、真实 DB、浏览器与合同检查。
2. 在备份与目标模式已审查的前提下，独立执行迁移任务。当前添加可空列可让旧应用继续服务；本地演练也重复执行迁移，第二次无变更。
3. 新版部署并核对健康、账户 Cookie、旧数据、修订和完整调查。
4. 发现故障时先区分进程存活与数据库就绪，按 TraceId 对照日志。回退到旧应用镜像，**保留扩展后的数据库模式**；核对旧应用写入没有抹掉新解释。
5. 再前滚并验证新字段/身份/笔记和结案。清理本次演练资源，保留镜像 ID、迁移与运行证据。

Down 会删除解释与修订时间，不能作为本变更的无损回退。若未来合同不再兼容，必须另做 expand/migrate/contract 分阶段设计及备份恢复验证。本阶段没有验证 Azure 部署、完整业务备份恢复、生产滚动升级或 SLA。
